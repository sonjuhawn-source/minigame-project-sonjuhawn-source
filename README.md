# Wave Rush

몰려오는 5개의 웨이브를 콤보와 회피로 돌파하고, 마지막에 등장하는 보스를 쓰러뜨리는 3D 액션 핵 앤 슬래시 게임입니다.

## 프로젝트 개요

- 장르: 3D 액션 핵 앤 슬래시 (웨이브 서바이벌 + 보스전)
- 개발 기간: 2026.05.15 ~ 2026.06.07 (핵심 기능 3주) · 이후 비동기 처리 리팩터링과 Firebase 연동 (~2026.06.23), 한글 폰트 보완 (2026.09)
- 개발 인원: 1명
- 사용 엔진: Unity 6 (6000.3.15f1) · URP
- 사용 언어: C#
- 사용 기술: Input System, Cinemachine, UniTask, ScriptableObject, Firebase (Authentication · Realtime Database, SDK 13.12.0)
- 출시 플랫폼: PC 빌드 (v0.3.0)
- 담당 역할: 기획, 프로그래밍, UI 구성, 테스트, 빌드
- 참고 게임: 검은사막, 마비노기

> 이 저장소에는 유료 에셋(`Assets/Imported/`, 학원 라이선스 제공분)이 저작권상 포함되어 있지 않습니다.  
> 클론한 프로젝트만으로는 정상 실행되지 않으며, 코드와 설계 확인용 저장소입니다.  
> Firebase 설정 파일도 보안상 제외했습니다. 설정 방법은 아래 [실행 방법](#실행-방법)에 적었습니다.

## 게임 설명

플레이어는 약공 콤보, 강공 콤보, 회피를 조합해 근접·엘리트·원거리 몬스터가 섞여 나오는 5개 웨이브를 처치합니다.  
웨이브 사이 휴식 구간에서는 모은 골드로 상점을 이용하고, 레벨업할 때마다 스탯을 직접 분배해 성장 방향을 정합니다.  
마지막 웨이브를 넘기면 보스가 등장하며, 거리에 따라 근접·돌진·원거리 패턴을 섞어 쓰는 보스를 쓰러뜨리면 클리어입니다.  
클리어 타임은 온라인 리더보드에 기록되어 다른 플레이어와 비교할 수 있습니다.

## 주요 기능

- 약공 3타 콤보, 강공 콤보(스태미나 소비)와 피니셔, 입력 방향 회피(무적 프레임)
- STR(힘) / AGI(민첩) / VIT(체력) / STA(스테미나) 스탯 분배와 경험치 레벨업
- 몬스터 3종: 근접 / 엘리트(예고 후 강공, 회피하면 캔슬) / 원거리(투사체 + 거리 유지)
- 직접 구현한 Behavior Tree 기반 보스: 근접·돌진·원거리 패턴을 거리와 확률로 선택
- 웨이브 → 상점(UI) → 다음 웨이브 → 보스전 흐름
- 골드, 포션, 상점(포션 +1 / HP 회복 / 랜덤 스탯 강화)
- 시작·일시정지·옵션·게임오버·클리어 UI, 데미지 팝업, 보스 HP바
- 일반·보스 BGM 전환, 애니메이션 이벤트 기반 효과음
- Firebase 로그인(이메일 가입·로그인, 익명 로그인)과 닉네임 등록
- 클리어 타임 온라인 리더보드 (클리어 시 자동 기록, 빠른 순 상위 5개 기록 표시)

## 조작법

- 이동: WASD 또는 방향키
- 시점 회전: 마우스
- 약공 콤보: 마우스 왼쪽 버튼
- 강공 콤보: 마우스 오른쪽 버튼 + 그 외 약공격 조합
- 회피: Space
- 포션 사용: E
- 일시정지: Esc

## 기술적으로 신경 쓴 부분

- **플레이어 상태는 Animator가 변경합니다.** 각 애니메이션 State에 붙은 `PlayerStateBehaviour`가 상태를 기록하고, 이동·전투 코드는 상태를 확인해 입력을 통과시키거나 막기만 합니다. AGI 스탯에 따라 모션 속도가 달라져도 모션과 상태가 어긋나지 않습니다. 강공 시작과 사망만 코드에서 즉시 확정합니다.
- **콤보 버퍼에 입력 큐를 쓰지 않았습니다.** 콤보 타이밍의 기준이 애니메이션이라, 트리거가 트랜지션에 소비될 때까지 남는 성질을 버퍼로 활용했습니다. 남은 트리거 때문에 회피 직후 공격이 튀어나오는 문제는 `SetTriggerExclusive`로 막았습니다. 회피는 반응성이 우선이라 버퍼 없이 즉시 재생합니다.
- **몬스터는 전이 규칙은 코드, 기준값은 데이터로 나눴습니다.** `IMonsterState`(Enter / Tick / Exit)로 상태를 분리하고, 감지·공격 거리, 경직 시간, 공격 종류는 `MonsterData`(ScriptableObject)에서 읽습니다. 새 몬스터는 코드 수정 없이 데이터로 추가합니다. 엘리트의 예고 모션 정리는 `Exit()`에 두어, 피격이나 사망으로 빠져나가도 모션이 남지 않습니다.
- **보스 Behavior Tree를 직접 구현했습니다.** BT는 매 프레임 루트부터 다시 평가하므로, 진행 중인 돌진·예고를 Blackboard 플래그로 기억하고 Continue 노드를 트리 맨 앞에 두어 다른 패턴으로 끊기지 않게 했습니다.
- **웨이브는 데이터 조립으로 구성합니다.** `WaveData`가 `MonsterData`와 마릿수를 참조하고, 마지막 웨이브의 `bossPrefabOverride` 필드로 보스 웨이브를 만듭니다. 보스 전용 분기 코드가 없습니다.
- **Firebase 초기화는 단계별 상태로 관리합니다.** `FirebaseInitializer`가 초기화 상태를 Pending / Ready / Failed로 관리하고, 인증·프로필·기록 매니저는 앞 단계를 `await`로 기다려 순서를 보장합니다. 로그인·저장 같은 호출은 예외를 던지지 않고 `(bool success, string error)`로 결과를 돌려주어, UI가 오류 문구를 그대로 보여줍니다. Realtime Database 주소는 `FirebaseConfig`(ScriptableObject)로 코드 밖에서 넣습니다.
- **로그인은 필수입니다.** 클리어 기록이 계정에 종속되는 구조라, 로그인을 마쳐야 시작 화면으로 넘어갑니다. 네트워크가 없으면 로그인할 수 없어 플레이도 할 수 없습니다. 오프라인 플레이를 허용하려면 로그인을 건너뛰는 경로와 기록 저장 분기를 따로 만들어야 해서, 이번 범위에서는 로그인 필수로 두었습니다.
- `IDamageable`, `IStatProvider` 인터페이스로 공격 판정과 UI가 구체 타입을 몰라도 동작하게 했습니다.
- HP·경험치·골드·포션·보스 HP UI는 이벤트 구독 방식으로, 값이 바뀔 때만 갱신합니다.
- `SwordHitbox`는 `HashSet<IDamageable>`로 한 번의 휘두르기에서 같은 대상이 여러 번 맞지 않게 했습니다.

## 문제 해결 경험

### 문제 1. UI를 여러 개 겹쳐 열면 게임이 먼저 재개되고 커서가 사라지는 문제

- 증상: 레벨업 스탯창이나 상점이 열린 상태에서 일시정지 창을 열었다 닫으면 마우스 커서가 사라져 패널을 클릭할 수 없었습니다. 레벨업과 웨이브 클리어가 동시에 일어나면 UI끼리 충돌하기도 했습니다.
- 원인: 각 패널이 `Time.timeScale`과 커서를 직접 제어해서, 하나를 닫을 때 다른 패널이 열려 있는지 확인하지 않았습니다.
- 해결: 일시정지와 커서 제어를 `PauseManager`로 모으고 `pauseCount`로 관리했습니다. 마지막 UI가 닫힐 때만 게임을 재개하고, 커서 표시도 같은 기준을 따릅니다.
- 배운 점: 여러 곳에서 동시에 요청할 수 있는 상태는 한 곳에서 관리해야 합니다.

### 문제 2. 빌드에서 이펙트가 처음 나올 때 프레임이 끊기는 문제

- 증상: 에디터에서는 괜찮았지만, 빌드에서 엘리트 몬스터 광역 공격과 보스 투사체가 처음 나올 때 순간적으로 멈췄습니다.
- 원인: 이펙트 셰이더가 처음 그려지는 시점에 컴파일되었습니다.
- 해결: `VFXPrewarmer`가 게임 시작 시 카메라 앞에 0.01 배율로 이펙트를 한 번 재생하고 2프레임 뒤 제거해, 플레이어가 보기 전에 컴파일을 끝내게 했습니다.
- 배운 점: 에디터와 빌드의 성능은 다르므로 빌드에서 직접 확인해야 합니다.

### 문제 3. 후반으로 갈수록 게임이 너무 쉬워지는 문제

- 증상: v0.3.0 빌드 플레이테스트에서 후반 강공 데미지가 240을 넘어 보스가 두 번에 쓰러졌습니다.
- 원인: 레벨업당 스탯 포인트 5와 STR 데미지 2배 보정이 겹쳐 후반 성장이 급격했습니다.
- 해결: 레벨업 포인트를 5에서 2로, STR 보정을 2배에서 1배로 낮추고, 상점 가격(5·5·2g → 15·10·4g)과 몬스터 보상을 조정했습니다. 5웨이브 누적 골드를 기준으로 예산을 계산해 수치를 정했고, 남는 골드는 가장 싼 랜덤 스탯 강화가 흡수하도록 했습니다.
- 배운 점: 밸런스 수치는 감으로 정하지 않고 누적 자원을 계산해 근거를 두어야 합니다. 다만 랜덤 스탯은 결과가 운에 좌우되는 한계가 남아 있습니다.

### 문제 4. 원거리 몬스터의 투사체가 발사 직후 자기 몸에 맞는 문제

- 원인: 몬스터 루트 오브젝트에만 태그가 있고, 모델의 자식 콜라이더에는 태그가 없어 태그 검사를 통과했습니다.
- 해결: 태그 검사에 더해 `GetComponentInParent`로 부모에 몬스터·보스 컨트롤러가 있는지 확인하도록 했습니다.
- 배운 점: 태그는 오브젝트 단위라, 여러 콜라이더로 구성된 대상은 구성 요소 기준으로 판별하는 것이 안전합니다.

### 문제 5. 닉네임 입력창의 한글 안내 문구가 네모(□)로 표시되는 문제

- 증상: 닉네임을 비워두고 확인을 누르면 나오는 한글 안내 문구가 네모로 표시되었습니다.
- 원인: 기본 폰트와 UI 폰트에 한글 글리프가 없었고, TextMeshPro 전역 폴백 폰트도 비어 있었습니다.
- 해결: 나눔고딕 폰트 에셋을 Dynamic 방식(1024 아틀라스, 멀티 아틀라스)으로 만들어 전역 폴백에 등록했습니다. 필요한 글자만 실행 중에 만들어서, 한글 전체를 미리 구운 33.6MB 에셋을 약 2MB로 줄였습니다.
- 배운 점: 폰트 폴백은 개별 텍스트가 아니라 전역 설정으로 한 번에 해결할 수 있고, Dynamic 폰트는 원본 폰트 파일이 연결되어 있어야 동작합니다.

## AI 활용 내용

이 프로젝트에서는 AI를 다음 작업에 활용했습니다.

- 설계 방향 검토와 구조에 대한 조언
- 오류 원인 분석과 디버깅 방향 제시
- 구현할 기능의 뼈대 코드 예시 확인 (실제 코드는 구조를 이해한 뒤 직접 작성)
- 발표 자료 다이어그램과 문서 구성 정리

AI의 제안은 바로 적용하지 않고, 프로젝트 구조에 맞는지 검토한 뒤 직접 작성하고 테스트했습니다.

## 실행 방법

1. 빌드 파일을 다운로드합니다.
2. 압축을 해제합니다.
3. 실행 파일을 실행합니다.
4. 조작법을 확인한 뒤 플레이합니다.

에디터에서 열 경우 Unity 6000.3.15f1에서 `Assets/Scenes/CharacterTestScene.unity`를 실행합니다. 단, 위에 적은 것처럼 유료 에셋이 없으면 정상 실행되지 않습니다.

Firebase 기능(로그인·리더보드)을 쓰려면 보안상 저장소에서 제외한 아래 파일을 직접 준비해야 합니다.

- `Assets/google-services.json` — Firebase 콘솔에서 받은 앱 설정 파일
- `Assets/StreamingAssets/google-services-desktop.json` — 위 파일로 Firebase Unity SDK가 생성하는 데스크톱용 설정
- `Assets/Resources/FirebaseConfig.asset` — `Create > Firebase Study > Firebase Config`로 만든 뒤 Realtime Database 주소(`databaseUrl`) 입력

## 테스트 케이스 기반 검증

빌드를 기준으로 테스트 케이스 191건을 작성해 수행했습니다. 기능 흐름을 실행 및 계정 / UI / 전투 기본 동작 / 전투 핵심 메커니즘 / 몬스터·보스 / 진행·시스템으로 나누고, 각 케이스에 사전 조건과 기대 결과, 중요도와 우선순위를 정의했습니다.

수행 중 발견한 결함은 이슈로 등록해 재현 방법과 원인을 기록하고, 수정 후 같은 케이스로 다시 검증했습니다. 아래는 그렇게 고친 것들입니다.

- 로그인 전 리더보드를 조회해 `Permission denied`가 발생하던 문제 — 인증 완료 후 조회하도록 수정 (#82)
- 자동 로그인 시 리더보드에 닉네임 대신 이메일이 저장되던 문제 — 저장 직전 프로필을 다시 확인 (#83)
- 같은 계정 기록이 중복 저장되던 문제 — `userId`를 키로 쓰고 더 빠른 기록일 때만 갱신 (#84)
- 네트워크 차단 시 로그인 오류 문구가 계정 문제로 표시되던 문제 — 연결 상태를 먼저 판정 (#85)

반대로 결함으로 보였으나 사양 확인 후 의도된 동작으로 판정해 되돌린 것도 있습니다. 원거리 몬스터가 발사 후 회복 중에도 후퇴하는 동작은 "거리 유지"라는 설계 의도에 맞아, 수정 대신 테스트 케이스의 기대 결과를 사양에 맞게 고쳤습니다 (#86).

## 알려진 문제

### 닉네임을 변경할 수 없음

- 현상: 등록한 닉네임을 바꿀 방법이 없습니다. 닉네임이 리더보드 표시명이라 한 번 정하면 고정됩니다.
- 원인: `ProfileEditUI`와 `UpdateNicknameAsync`는 구현되어 있으나 씬에 배치되지 않아 진입 경로가 없습니다.
- 개선 계획: 시작 화면에 프로필 편집 패널과 진입 버튼을 연결할 예정입니다.

## 회고

이번 프로젝트를 통해 전투, 몬스터 AI, 보스, 웨이브, 성장, UI까지 액션 게임 한 판의 흐름을 혼자 완성하고 빌드까지 경험했습니다.  
일반 몬스터는 FSM, 보스는 Behavior Tree로 목적에 맞게 구조를 나누고, 이벤트와 ScriptableObject로 데이터와 로직을 분리하는 방법을 익혔습니다.  
빌드에서만 드러나는 셰이더 렉이나 투사체 자기 충돌 같은 문제를 직접 찾아 고치면서, 에디터 밖에서 검증하는 습관의 중요성을 배웠습니다.  
완성 이후에는 테스트 케이스를 기준으로 전체 기능을 다시 검증했습니다. 기대 결과를 먼저 정의하고 확인하니, 눈으로 볼 때는 정상처럼 보이던 문제(자동 로그인 시 이메일 저장, 로그인 전 리더보드 조회 실패)가 드러났습니다. 반대로 결함으로 의심한 동작이 사양 확인 후 의도된 것으로 밝혀지기도 했는데, 이때는 코드가 아니라 기대 결과를 고쳐야 한다는 점도 함께 배웠습니다.  
Firebase를 붙이면서는 네트워크 초기화가 끝나기 전이나 실패한 상황에서도 게임이 멈추지 않도록 비동기 순서와 실패 처리를 설계하는 경험을 했습니다.  
다음에는 몬스터 공격 상태 분기를 `MonsterData` 쪽으로 옮기고, 코드에 남아 있는 거리 보정값을 데이터로 빼며, 중복된 보스 Continue 노드를 공통 구조로 묶어 확장성을 높이고 싶습니다.
